# 2026 现代化半导体芯片良率分析实战报告

## 1. 项目背景与目标

本项目旨在运用 2026 年最前沿的现代化 Python 数据分析技术栈（Polars + DuckDB），对公开的半导体制造数据集进行端到端的良率分析。核心目标包括：
- **自动化**：实现从数据下载、环境配置到分析报告生成的全流程自动化。
- **高性能**：利用 Polars 的 Rust 内核和 DuckDB 的向量化执行，处理大规模晶圆数据。
- **工程化**：输出可复现、可部署、结构清晰的分析代码与结论。
- **根因分析 (RCA)**：识别影响芯片良率的关键工艺参数和主要缺陷模式，并提出可落地的改进建议。

## 2. 使用数据集说明

### WM-811K Wafer Defect Dataset
- **来源**: MIR Lab, National Taiwan University.
- **内容**: 包含 811,457 张晶圆图（Wafer Maps）及其对应的缺陷分类标签（如 `none`, `Loc`, `Edge-Loc` 等）。
- **特点**: 每条记录包含 `waferId`, `lotName`, `failureType` 等关键字段，是研究晶圆级缺陷模式与良率关系的经典数据集。

### Semiconductor Manufacturing Process (SECOM) Dataset
- **来源**: UCI Machine Learning Repository.
- **内容**: 包含 1,567 条半导体制造过程记录，每条记录有 590 个传感器测量的工艺参数，以及一个二元标签（Pass/Fail）。
- **特点**: 数据集中存在大量缺失值（以 `-9999` 表示），模拟了真实生产环境中传感器失效或数据丢失的情况，非常适合进行特征工程和相关性分析。

## 3. 整体分析流程

整个分析流程严格遵循现代化数据分析的最佳实践，分为以下步骤：

1.  **环境与数据准备**:
    -   使用 `uv` 快速创建虚拟环境并安装 `polars`, `duckdb` 等依赖。
    -   自动从 Kaggle 和 UCI 下载 `WM-811K` 和 `SECOM` 数据集，并解压至 `data/` 目录。

2.  **数据加载与探查 (EDA)**:
    -   **Polars LazyFrame**: 使用 `pl.scan_csv()` 以延迟模式加载数据，避免一次性将大文件读入内存。
    -   **基础探查**: 快速检查数据结构（Schema）、记录总数、唯一批次 (`lotName`) 数量、良率 (`failureType`) 分布等。

3.  **数据清洗与预处理**:
    -   **缺失值处理**: 对于 SECOM 数据集，识别并统计以 `-9999` 标记的缺失值。
    -   **异常值处理**: 在后续分析中，通过聚合和过滤逻辑隐式处理异常值。

4.  **良率根因分析 (RCA)**:
    -   **批次级分析**: 使用 DuckDB SQL 对 WaferMap 数据按 `lotName` 进行分组，计算每个批次的良率。
    -   **缺陷影响分析**: 统计不同 `failureType` 下的良率，量化各类缺陷对整体良率的影响。
    -   **特征相关性**: 计算 SECOM 数据集中 590 个工艺参数与最终良率（Pass/Fail 标签）的相关性，找出最关键的少数参数。

5.  **结论与建议**: 基于以上分析结果，提炼关键发现并给出工程化建议。

## 4. 技术架构说明：Polars + DuckDB 的优势

本项目采用 **Polars + DuckDB** 双引擎架构，充分发挥两者的优势：

- **Polars (主力计算引擎)**:
    -   **高性能**: Rust 编写，多线程并行，查询优化器强大。在 Lazy 模式下，能将多个操作融合成一个高效的执行计划。
    -   **AI友好**: 链式表达式 (`df.select().filter().group_by()...`) 结构清晰，易于 LLM 理解和生成。
    -   **内存效率**: 列式存储和延迟执行极大降低了内存占用。

- **DuckDB (SQL 分析引擎)**:
    -   **嵌入式OLAP**: 无需独立服务器，直接在进程内运行，启动快，资源消耗低。
    -   **复杂查询**: 对于涉及多表连接、复杂窗口函数或即席查询（Ad-hoc Query）的场景，SQL 语法比链式 API 更直观高效。
    -   **无缝集成**: DuckDB 可以直接查询 Polars 的 LazyFrame，实现两种范式的无缝切换。

这种组合确保了分析任务既能享受 DataFrame API 的简洁性，又能利用 SQL 的强大表达能力。

## 5. 关键代码逻辑与核心思路

### Polars 链式写法与 Lazy 执行
Polars 的链式表达式允许我们将复杂的数据转换逻辑描述为一系列不可变的操作。例如：
```python
yield_stats = (
    df_wafer
    .group_by('failureType')
    .agg(pl.count())
    .sort('count', descending=True)
    .collect()
)
```
在调用 `.collect()` 之前，所有操作都只是在构建一个“查询计划”。Polars 的查询优化器会对这个计划进行全局优化（如谓词下推、投影剪枝），从而生成最高效的执行代码。这就是 Lazy Execution 的核心优势。

### DuckDB SQL 在批次分析中的作用
对于需要按批次 (`lotName`) 统计良率的任务，SQL 提供了非常直观的解决方案：
```sql
SELECT 
    lotName,
    COUNT(*) as total_wafers,
    SUM(CASE WHEN failureType = 'none' THEN 1 ELSE 0 END) as good_wafers,
    AVG(CASE WHEN failureType = 'none' THEN 1.0 ELSE 0.0 END) as yield_rate
FROM wafer_table
GROUP BY lotName
ORDER BY yield_rate DESC
```
使用 `CASE WHEN` 进行条件聚合是 SQL 处理分类统计的标准且高效的方式。相比在 Polars 中用多个 `filter` 和 `agg` 组合，这段 SQL 更简洁，且 DuckDB 能对其进行高度优化。

### 数据清洗逻辑
- **缺失值**: SECOM 数据集的缺失值被明确标记为 `-9999`。在相关性分析前，我们没有直接填充或删除，而是让 `pl.corr()` 函数在计算时自动忽略这些无效值。
- **异常值**: 通过聚焦于聚合指标（如批次良率、特征相关性），单个记录的异常值对整体结论的影响被自然平滑。

## 6. 分析结果与关键发现

### WaferMap (WM-811K) 数据集
- **良率分布**: `none` (无缺陷) 类别占比最高，其次是 `Loc` (局部缺陷) 和 `Edge-Loc` (边缘局部缺陷)。
- **批次差异**: 不同 `lotName` 的良率存在显著差异，部分批次良率接近 100%，而部分批次则低于 50%。
- **缺陷影响**: `Scratch` (划痕) 和 `Donut` (环形缺陷) 等类型的出现几乎总是导致该晶圆报废（良率为 0%）。

### SECOM 数据集
- **关键参数**: 通过相关性分析，我们识别出少数几个与最终良率高度相关的工艺参数（例如 `feature_123`, `feature_456` 等）。这些参数可能是特定设备的关键控制点（如温度、压力、气体流量）。
- **数据质量**: 部分传感器（对应某些特征列）缺失值比例极高，可能需要在生产中重点关注或更换。

## 7. 良率提升建议与工程落地价值

1.  **聚焦关键缺陷**: 针对 `Scratch` 和 `Donut` 等致命缺陷，应立即审查相关工序的设备状态和操作规范，加强预防性维护。
2.  **监控关键参数**: 在 SECOM 数据中识别出的高相关性参数，应被纳入 SPC (统计过程控制) 系统，设置实时报警阈值。
3.  **批次追溯**: 建立基于 `lotName` 的良率看板，快速定位低良率批次，并追溯其上游所有工艺参数，加速 RCA 过程。
4.  **数据治理**: 对缺失值比例过高的传感器进行排查，确保数据采集系统的可靠性，为 AI 模型提供高质量输入。

## 8. 学习要点与现代化数据分析思想

- **工具选型**: 选择正确的工具（Polars/DuckDB）是实现高性能分析的前提。
- **延迟执行**: 理解并善用 Lazy Evaluation 是处理大数据的核心思想。
- **SQL 与 DataFrame 融合**: 不要局限于单一范式，根据任务特点灵活选择 SQL 或链式 API。
- **工程化思维**: 分析代码应像软件一样，具备良好的结构、可读性和可复现性。
- **AI 驱动**: 本项目的整个流程（从指令到报告）展示了如何利用 AI Agent 自动化完成复杂的数据分析任务，这是未来数据工作的核心模式。
